# VikingCompanion — мод

BepInEx-плагин для Valheim 1.0. Добавляет компаньона и общается с [мостом](../CompanionBridge/README.md). Установка, настройки и игра описаны в [основном README](../README.md).

## Сборка

```sh
dotnet build -c Release                  # собрать и положить DLL в BepInEx/plugins/VikingCompanion
dotnet build -c Release -p:Deploy=false  # только собрать, например пока игра запущена
```

Путь к игре берётся из `../local.props` (образец — `local.props.example`) или из `-p:ValheimDir=...`. Без них используется стандартная папка Steam на macOS. Приватные поля игры открываются при компиляции через [BepInEx.AssemblyPublicizer](https://github.com/BepInEx/BepInEx.AssemblyPublicizer).

Путь к `CompanionBridge` зашивается в DLL при сборке (атрибут `AssemblyMetadata("BridgeDir")`). Это значение по умолчанию для `Bridge.Python` и `Bridge.Script` в конфиге.

## Как устроено

| Файл | Что внутри |
|---|---|
| `CompanionPrefab.cs` | Префаб компаньона — копия префаба игрока: `Player` заменён на `Humanoid` + `MonsterAI` с фракцией `Players`. Модель, анимации и снаряжение игрока работают как есть. Снаряжение `Имя:число` — расходное (стрелы) |
| `Companion.cs` | Режимы поверх `MonsterAI`: следовать, стоять, рубить и добывать, собирать растения, охотиться, подбирать, отдать, сложить в сундук, взять из сундука. Очередь шагов плана и общий отчёт в конце. Лук: прицеливание и анимация натяжения вручную, ИИ-дальность лука через свою копию `SharedData` |
| `Plan.cs` | Шаг плана `{do, what, count}` из ответа моста |
| `Catalog.cs` | Растения (ягоды, грибы, травы, «земля», посевы) и дичь по префабам игры; понимание `what` по основам слов и категориям («ягоды», «грибы», «руда», «стрелы») |
| `WorldScan.cs` | Поиск деревьев, камня, растений, сундуков по `ZNetScene.m_instances` с картой «хеш префаба → тип». Дичь — по `Character.GetAllCharacters` |
| `BjornChest.cs` | «Сундук Бьёрна»: копия `piece_chest` с +10 глаз грейдварфа в рецепте, своим именем и отливом. Регистрируется в `ZNetScene` и в таблице молота |
| `SettingsTab.cs` | Вкладка «Бьёрн» в окне настроек игры: `ISettingsTab` из копий родных элементов (переключатели, ползунки, флажки), свои поля ввода на TMP |
| `CompanionManager.cs` | Появление и перенос к игроку, события мира для реплик, заметки для памяти (смерти, боссы, ремесло, постройки, новые земли), сводка состояния для LLM, разбор команд по ключевым словам, если моста нет |
| `Bridge.cs`, `Json.cs` | HTTP к мосту в фоновом потоке, ответы — в главном. `JsonUtility` из сборки мода теряет вложенные объекты, поэтому JSON пишется и разбирается своим `Json.cs`. Настройки уходят мосту файлом при запуске (`--config`) и через `/v1/config` при каждом изменении |
| `Voice.cs` | Рация на R: старт и стоп записи в мосте, опрос распознанного текста, окно — копия префаба реплики NPC из самой игры |
| `Patches.cs` | Патчи Harmony: управление ИИ, выбор оружия (топор или лук), натяжение лука и баллистика стрелы, события для памяти, вкладка в настройках, имя и подсказки, глушение «Убрать оружие» на R |
| `Plugin.cs` | Настройки и автозапуск моста (`arch -arm64`, мост следит за PID игры и завершается вместе с ней) |

## Отладка

- `Debug.DebugLog = true` в конфиге пишет цели, удары и подбор в `BepInEx/LogOutput.log`.
- `VCOMP_LOG_STATE=1` в окружении игры заставляет мост писать в свой лог состояние мира, которое прислала игра.
